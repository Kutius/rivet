# Rivet main repository

This is the official Rivet main catalog. It is served at:

~~~text
https://kutius.github.io/rivet/index.json
https://kutius.github.io/rivet/index.json.sig
~~~

## Layout

~~~text
packages/*.toml       package manifests
sources.toml          curated GitHub repositories for bulk sync
artifacts/            demo artifacts checked in for the hello package
index.json            generated by `.\scripts\repo.ps1 build`
index.json.sig        Ed25519 signature over the exact index.json bytes
~~~

## Maintainer workflow

Most packages are one command. `rv-repo add` reads the latest GitHub release, picks the Windows x64 asset, downloads it, infers the archive layout and executable name, computes SHA-256, writes the manifest, and rebuilds the index:

~~~powershell
.\scripts\repo.ps1 add BurntSushi/ripgrep --path repo\main
.\scripts\repo.ps1 add jqlang/jq --path repo\main
~~~

Use overrides when a repository needs them:

~~~powershell
.\scripts\repo.ps1 add owner/repo --path repo\main --name package-name
.\scripts\repo.ps1 add owner/repo --path repo\main --asset windows-amd64.zip
.\scripts\repo.ps1 add owner/repo --path repo\main --bin bin\tool.exe
~~~

`rv-repo add` refuses to overwrite an existing manifest. The generated file is a normal manifest; review its description, license, tags, and bin entries before committing.

## Bulk additions

[sources.toml](sources.toml) is the curated list of GitHub repositories that should exist in the catalog. `sync` adds every repository that does not already have a manifest, skips the rest, and isolates failures so one bad candidate does not abort the batch:

~~~powershell
.\scripts\repo.ps1 sync repo\main --dry-run
.\scripts\repo.ps1 sync repo\main --limit 10
.\scripts\repo.ps1 sync repo\main --allow-failures
~~~

The compact form is one repository per entry:

~~~toml
repositories = [
  "BurntSushi/ripgrep",
  "sharkdp/fd",
]
~~~

Add a `[[source]]` block when auto-detection needs help:

~~~toml
[[source]]
repository = "cli/cli"
name = "gh"

[[source]]
repository = "owner/repo"
asset = "tool-windows-amd64.zip"
bin = "bin/tool.exe"
~~~

Run imports in batches of 10–20, then verify the result before committing. `sync` rebuilds the index once at the end; it does not sign it.

~~~powershell
cargo build --release --bin rv --bin rv-repo
.\scripts\verify-catalog.ps1 -Root repo\main
~~~

The verification script installs every package into a temporary `RIVET_ROOT`, checks the hashes with `rivet verify`, and runs a version command for each exposed command. The weekly [Catalog verify workflow](../../.github/workflows/catalog-verify.yml) runs the same check.

Refresh every GitHub-hosted package to its latest release:

~~~powershell
.\scripts\repo.ps1 update repo\main --check
.\scripts\repo.ps1 update repo\main
~~~

`--check` prints current and available versions without writing. `rv-repo update` downloads each new asset, verifies that the existing bin paths still exist, updates version/URL/SHA-256, and rebuilds the index. `--package <name>` limits the run.

The [Catalog update workflow](../../.github/workflows/catalog-update.yml) runs daily. It updates GitHub-hosted packages, signs `index.json` with the encrypted `RIVET_SIGNING_KEY_B64` Actions secret, smoke-installs the changed packages, and pushes the result to `master`.

Set a GitHub token to avoid the unauthenticated API limit of 60 requests per hour:

~~~powershell
$env:GITHUB_TOKEN = gh auth token
~~~

CI signing uses the `RIVET_SIGNING_KEY_B64` secret. The same command still works locally with the key file:

~~~powershell
.\scripts\repo.ps1 build repo\main
.\scripts\repo.ps1 sign repo\main --key <key-path>
~~~

Commit the manifests, `index.json`, and `index.json.sig`, then push to master. The Pages workflow publishes the catalog.

## Scaling the catalog

The main catalog is deliberately curated, not a mirror of every Windows package. A practical ceiling is roughly 100 high-value portable CLIs; the long tail belongs in taps or a separate community index.

Candidate sources, in order of quality:

1. Hand-picked tools that Windows developers actually use.
2. Awesome lists and project directories, filtered to repositories with Windows x64 release archives.
3. Scoop and winget metadata as discovery input only. Re-resolve the upstream GitHub release and regenerate the manifest; do not copy their manifests or installers.

Import in batches of 10–20, run the verification script, and commit only a green batch. This keeps a bad asset or a changed archive layout out of the signed catalog.

## What still needs a human

- Non-GitHub release URLs.
- Packages whose archive has several executables and no obvious match; pass `--bin`.
- Packages with an installer instead of a portable archive; Rivet does not run arbitrary install hooks.
- New package discovery and quality decisions. `sources.toml` is curated; do not bulk-import Scoop or winget manifests without re-resolving the upstream release and running the verification script.
- Date-versioned releases such as rust-analyzer nightly builds; they need a deliberate version policy rather than automatic semver extraction.

The private key is never committed. It is stored as an encrypted GitHub Actions secret for the main catalog; protect `master` and workflow changes accordingly. The public key is embedded in the client as the default trusted catalog key.
