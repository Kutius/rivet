# Taps

A tap is a Git repository of package manifests, in the Homebrew style. Taps are optional and explicitly trusted by the user.

## Layout

~~~text
my-tap/
  packages/
    hello-1.0.0.toml
    hello-1.1.0.toml
  artifacts/          # optional, for relative URLs
  index.json          # optional, generated by .\scripts\repo.ps1 build
~~~

If a tap has no index.json, `rivet update` builds one locally from packages/*.toml.

## Add a tap

From GitHub owner/repo:

~~~powershell
rivet tap add owner/repo
~~~

This clones https://github.com/owner/repo.git with depth 1. From an explicit Git URL or local path:

~~~powershell
rivet tap add demo https://example.invalid/demo-tap.git
rivet tap add demo C:\src\demo-tap
~~~

A non owner/repo name requires an explicit URL. Tap names are validated; . and .. are rejected.

## Use a tap package

Tap packages are namespaced by tap name:

~~~powershell
rivet install demo/hello
rivet info demo/hello
~~~

If a package exists in both the main repo and a tap, use repo/name to disambiguate.

## Refresh and remove

~~~powershell
rivet update          # git pull --ff-only for every tap, then rebuild the local index
rivet tap list
rivet tap remove demo
~~~

`rivet update` never changes installed packages; `rivet upgrade` does.

## Trust

Taps are trusted because the user adds them. The beta does not have a central verified-tap registry. If a tap ships a signed index.json, its signature is checked when a trusted key is configured; an unsigned tap index remains usable. Do not add a tap whose maintainer you do not trust.
